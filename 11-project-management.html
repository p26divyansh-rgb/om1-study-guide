Critical Path
Critical Path Method — core formulas FORWARD PASS (left to right): computes Earliest Start (ES) and Earliest Finish (EF) ES(activity) = max(EF of all its predecessors) [ES = 0 for start activities] EF(activity) = ES + Duration BACKWARD PASS (right to left): computes Latest Start (LS) and Latest Finish (LF) LF(activity) = min(LS of all its successors) [LF = Project duration, for end activities] LS(activity) = LF − Duration SLACK (Float) = LS − ES = LF − EF CRITICAL PATH = the longest path through the network = path where slack = 0 for every activity PROJECT DURATION = length (sum of durations) of the critical path
Exam fact (was literally MCQ #10 in 2025): the total slack of any activity on the critical path is always zero — that's the definition of "critical." The critical path itself is the longest path (not shortest), and represents the minimum possible project duration.
Worked Example — Forward/Backward Pass

Activities: A(3, no pred) → D(5, pred A) → G(4, pred B,D,E); B(6, no pred); C(2, no pred) → E(2, pred C); A → F(7).

Forward pass gives EF: A=3, B=6, C=2, D=8, E=4, F=10, G=12 → project duration = 12 weeks.

Backward pass from LF=12 gives slack: A=0, D=0, G=0 (critical path A–D–G); B has slack 2; C has slack 4; E has slack 4; F has slack 2.

Critical Path = A → D → G, Duration = 12 weeks.

Project Crashing

Crashing = spending extra money to shorten a critical activity's duration, in order to shrink total project time (e.g., to avoid a late-delivery penalty).

Crashing rules 1. Only CRITICAL activities are worth crashing (shortening a non-critical activity doesn't shorten the project). 2. Crash period-by-period (e.g., one week at a time), re-checking the critical path after each step. 3. Pick the critical activity with the lowest Cost Slope = (Crash Cost − Normal Cost) / (Normal Time − Crash Time). 4. Watch out for PARALLEL critical paths — once multiple paths become simultaneously critical, you may need to crash one activity on EACH parallel path (or a shared activity) to gain even one more week.
Worked Example — Crashing

Critical path A–D–G (12 weeks). Cost slopes: A=$5,000/wk, D=$4,000/wk, G=$7,000/wk. Cheapest is D → crash D by 1 week → project time = 11 weeks, cost = Normal($61,000) + $4,000 = $65,000.

Crash D again → path becomes 10 weeks, but now 3 paths are simultaneously critical: A-D-G, B-G, A-F. To shrink further, cheapest combo is crashing F and G together ($3,000+$7,000) rather than crashing 3 separate activities — always check whether one shared activity (like A) can shorten multiple paths at once before crashing them individually.

Uncertainty & Risk in Projects

  • Every activity-time estimate rests on assumptions — CPM outputs are only as good as those assumptions.
  • The critical path is dynamic — it can shift as activities slip or are crashed.
  • A project manager's job goes well beyond running the CPM calculation.
Risk categoryExamples
FinancialPenalty clauses, exchange-rate swings
MarketingDemand/market changes, brand image
TechnologyTie-up/partner risk, obsolescence
Operations/ExecutionResource availability, delays in activity durations

Managing risk: maintain redundancy of resources, monitor & report frequently, transfer risk (e.g., contracts/insurance), and share risk with partners.
