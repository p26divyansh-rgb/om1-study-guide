Topic 12 of 12 · Inventory build-up diagrams, batch/setup capacity trade-offs, and reading a full production system.

Inventory Build-Up Diagrams (Queueing over time)

These questions give a time-varying arrival rate and a (possibly changing) service/processing capacity, and ask you to track the queue over time. Core method:

Queue tracking logic For each time interval: Change in Queue = Arrival Rate − Service (Capacity) Rate [if positive → queue grows; if negative → queue shrinks, floor at 0] Queue(end of interval) = Queue(start) + (Arrival Rate − Capacity) × interval length Peak Queue = the highest point on this cumulative build-up curve Longest wait = found by matching a specific unit's arrival point against the cumulative "departures" curve (This is precisely a Little's Law style diagram: the vertical gap between the cumulative-arrivals and cumulative-departures curves = instantaneous inventory/queue; the horizontal gap = wait time for the unit arriving at that point.)
Style of question (2025 exam: Delhi T3 security)

Arrivals vary in three time bands (25/min, then 40/min, then 20/min); capacity = 5 lanes × 5/min = 25/min, with 2 extra lanes triggered once queue > 150, and a machine going offline for a period. You must (a) build the cumulative arrivals vs. departures diagram, (b) find peak queue & when it occurs, (c) find the longest wait and which arrival experiences it, and (d) evaluate a "proactive" policy change (open extra lanes earlier) by comparing peak queue and max wait under both policies.

Approach: break the timeline into pieces wherever arrival rate OR capacity changes; track cumulative queue at each breakpoint; the moment queue crosses a policy threshold (e.g., 150), capacity changes for subsequent intervals too.

Batch Processing & Setup-Time Capacity (e.g., Gene Cattie Enterprises case)

When a single resource is shared by multiple products with a changeover/setup time, capacity depends on batch size:

Capacity with setup times Time per batch = Setup time + (Batch size × Run time per unit) Effective Capacity (units/time) = Batch size / Time per batch ⇒ Larger batches amortize the fixed setup time over more units → HIGHER effective capacity ⇒ Smaller batches → more frequent setups → LOWER effective capacity, but LOWER flow time / WIP (Little's Law trade-off!)
This is the classic "batch size trade-off": bigger batches raise throughput capacity (fewer setups) but increase average inventory/WIP and flow time (Little's Law: I = R×T — units sit longer waiting for a full batch to complete). Line-balancing and CODP thinking both connect back to this same batch-size vs. flow-time trade-off.

Reading a full production system as a chain of resources

  1. Compute the (batch-adjusted) capacity of each resource/department independently.
  2. The system bottleneck = the resource with the lowest capacity once you account for the actual product mix moving through it (a resource used by multiple products may have less capacity "left over" for one product than it looks like in isolation).
  3. System throughput = bottleneck's capacity (you can never produce faster than your slowest necessary resource).
  4. Use Little's Law (I = R×T) with the actual inventory data at each stage to compute total average flow time through the whole factory.
